  it; remaining entries renumbered correctly.
- After deleting the bogus entry, Shorepoint's (Work Experience 1) actual Role Description field came back blank
  ("No Response") -- caught this on the Review page and had to go back through the wizard (Back x4) to My Experience
  to refill it manually before resubmitting. Always spot-check every Role Description field individually after any
  entry deletion, not just the entry counts/titles.
- Date field for the CC-305 Self-Identification form uses a masked MM/DD/YYYY input that mis-parses a plain
  "07/31/2026" typed string (fills as "07/DD/3120"). Fix: click the field, Ctrl+A, Delete, then type digits only
  ("07312026") -- the mask correctly auto-formats digit-only input.
- The Review page's "Please check one of the boxes below" (disability status) radio and the Date field both
  silently reset to blank/error after navigating Back through the wizard and Next-ing forward again once already
  (a stale-validation-state quirk) -- re-verify and re-select on every pass back through Self Identify before
  clicking Next again, don't assume a value that was correct on a previous pass is still set.
- Review page's "My Experience" section visually renders only Work Experience 1 in the summary (jumps straight
  from Work Experience 1's Role Description to the Education section) even though Work Experience 2-4 are present
  and correct in the underlying form data (confirmed via get_page_text on the My Experience step itself, showing
  all 4 entries intact with correct titles/companies/dates/descriptions). This looks like a Review-page display-only
  quirk specific to this tenant, not actual data loss -- don't panic-resubmit if this shows up again, but do
  independently verify via the My Experience step's own page text before trusting the Review summary.
- No email verification code step after Submit on this tenant (unlike Uber's Oracle HCM flow) -- the on-page
  "Congratulations! Your application has been successfully submitted." modal is the actual confirmation.
